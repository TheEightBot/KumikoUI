Branch reviewed: `feature/uno-platform-port` @ `4938125` (PR #9, 17 commits ahead of `main`, merge-base `a11a5aa`). All paths are relative to the checkout at `/Users/mstonis/Developer/KumikoUI` (on that branch); every cited `.cs`/`.md`/`.csproj`/workflow file was diffed against that working tree and is byte-identical to the commit (the working tree only adds IDE noise, a local `docs/release-readiness/` folder and an uncommitted edit to `samples/SampleApp.Uno/Platforms/iOS/PrivacyInfo.xcprivacy`, none of which are cited). Review date 2026-10-22. External facts verified today: .NET 9 end of support is **2026-11-10** (Microsoft devblogs / support policy); the highest stable `Uno.Sdk` on nuget.org is **6.7.30** (7.0 is `-dev`); `SKCanvasElement` lives in `Uno.WinUI.Graphics2DSK`, which the Uno.Sdk already adds for `SkiaRenderer` heads and which is already a direct dependency of `KumikoUI.Uno` on every head (`obj/project.assets.json` of the branch checkout).

---

## (a) Summary

- **Structurally the port is sound and better than MAUI in places** — Core/SkiaSharp are reused untouched (one additive Core change), the `DependencyProperty` surface is 1:1 with MAUI, attach/detach is idempotent, timers stop on `Unloaded`, pointer coordinates are already DIPs, and pointer/keyboard modifiers actually work (MAUI's `SKTouch`/Entry paths carry none). `KumikoFonts` is a cleaner font story than MAUI's sample-private helper.
- **It ships on `net9.0-*` heads 19 days before .NET 9 leaves support (2026-11-10)**, pinned to `Uno.Sdk 6.5.31` while 6.7.30 is current, with the pin duplicated inline in three csproj files because of a `global.json` misconception. Retargeting to `net10.0` heads is a one-flag change but must happen before a `v1.0.0` tag.
- **The hidden-`TextBox` keyboard proxy is the right idea but has release-grade rough edges**: the proxy path swallows *every* mapped key regardless of Core's `Handled` (keyboard trap — Tab/Shift+Tab/Escape can never leave the grid), the proxy is exposed to screen readers and to hit-testing at the visual centre of the grid, `ResetProxy()` after every `TextChanged` breaks CJK IME composition by construction, and the commits themselves state WASM/iOS/Android typing was never exercised.
- **Accessibility regressed versus MAUI**: the control derives from `Grid` (a `Panel`) with no automation peer, and the default `GridDescription` is never applied, so the whole grid is invisible to Narrator/VoiceOver/TalkBack; MAUI at least sets a semantic description and a rows/columns hint.
- **Perf/packaging/docs are not 1.0-ready**: software `SKXamlCanvas` (+ extra buffer copy) driven by 16 ms `DispatcherTimer` repaints on every Skia-rendered head when `SKCanvasElement` is already referenced; ~1,200 AndroidX `content/` entries in the nupkg are documented as "acceptable"; `UseKumikoUI` is a no-op that costs a package dependency; the root `README.md` (embedded in the nupkg) has zero Uno content; `docs/uno/README.md` still says "No `KumikoUI.Uno` code exists yet"; CI never builds `SampleApp.Uno` although the csproj and docs claim it is CI-verified.

## (d) Questions for the maintainer

1. **Runtime target**: is staying on `net9.0` for `src/` deliberate given .NET 9 leaves support on 2026-11-10? If the whole stack moves to `net10.0`, do it before the `v1.0.0` tag so the first published `KumikoUI.Uno` is not born out-of-support (UNO-01).
2. **Keyboard contract**: should Tab at the last editable cell (and Escape with nothing selected) leave the grid? Core marks Tab handled unconditionally (`GridInputController.cs:352-365`); the Uno proxy additionally swallows everything (UNO-02). What is the intended exit gesture?
3. **Right-click**: Core never reads `GridPointerEventArgs.Button` (no references outside `EditSession.cs:482`), so a right-click selects/edits exactly like a left-click on both hosts. Is a context-menu/`RowRightTapped` event planned, and should the host suppress Secondary presses until then?
4. **Grid-level `IsReadOnly`/`AllowSorting`/`AllowFiltering`** are dead on both hosts (UNO-10). Fix in Core (preferred) or remove them from the public surface before 1.0?
5. **Clipboard**: `DrawnTextBox` raises `CopyRequested`/`PasteRequested` (`src/KumikoUI.Core/Components/DrawnTextBox.cs:178-182`) but `EditSession` does not surface them and neither host wires a platform clipboard. Is Ctrl+C/V inside editors a 1.0 feature? (Uno host would use `Windows.ApplicationModel.DataTransfer.Clipboard`.)
6. **Package size budget**: are ~1,200 AndroidX content entries and the `Uno.WinUI.Lottie`/`Uno.Resizetizer`/`Uno.Settings.DevServer`/`Microsoft.Extensions.Hosting.Abstractions` dependencies acceptable in the published nupkg (UNO-09)? Why is Lottie referenced when only `SkiaRenderer` is requested?
7. **Mac Catalyst**: README matrix, 04 §6 and the csproj `Description` promise it; the template omitted the head and the sample has none. Target it (macOS is served by the desktop head) or drop the claim?
8. **Core change in the Uno PR**: `PinBottomSummaryRows` (`e78087e`) changes MAUI rendering too and has no test. Should it ship in this PR, and is the default `true` (behaviour change for existing MAUI users) intended?
9. **Theme**: port the `Theme` DP and/or follow `ActualTheme` by default (UNO-15)? Today a dark Uno app gets a white grid.
10. **Render surface**: appetite for `SKCanvasElement` in 1.0 vs 1.1 (UNO-06)? It is the Uno-recommended path and already referenced.
11. **`UseKumikoUI`**: keep (and make it do something) or delete before it becomes a compatibility obligation (UNO-12)?
12. **Hover**: is a Core `Hover` action acceptable so desktop hosts can show resize cursors (UNO-20)?
