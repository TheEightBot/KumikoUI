# KumikoUI 1.0 readiness review — SkiaSharp backend + MAUI host + MAUI sample

Reviewed at commit `59825e2` (main == worktree HEAD; `feature/uno-platform-port` does not touch any file in this slice except `.github/workflows/{ci,publish}.yml`, which only add Uno jobs). Nothing in the repo was modified. Evidence was gathered by reading every file in the slice and by building locally with the installed .NET 10.0.401 SDK / MAUI workload 10.0.110 (logs in this scratchpad: `build-maccatalyst.log`, `build-lib-ios.log`, `build-lib-android.log`, `build-sample-maccatalyst-override.log`).

## (a) Summary

- **The MAUI package no longer builds for Mac Catalyst on current toolchains.** `SupportedOSPlatformVersion` 15.0 is rejected by the .NET 10 MacCatalyst SDK 27.0 ("lower than the minimum value '17.0'", `KumikoUI.Maui.csproj:20`, `SampleApp.Maui.csproj:35`). CI was last green on 2026‑06‑30 and installs the *latest* `maui` workload, so the next uncached run will fail the same way. README Requirements (`README.md:900-902`) advertise 15.0+.
- **Several advertised MAUI properties are inert.** `IsReadOnly`, `AllowSorting`, `AllowFiltering` are BindableProperties with no `propertyChanged` and no consumer anywhere in Core (`DataGridView.cs:344-352, 411-432`); the sample's "Toggle Filtering" button and the `AllowSorting="True"` XAML attributes do nothing. `IsReadOnly` additionally shadows `Layout.IsReadOnly` (`IList<IView>`) via `new`.
- **The SkiaSharp backend crashes on an unknown font family on Android/Windows and has no glyph fallback.** `SKTypeface.FromFamilyName` is nullable (compiler CS8601/CS8603 at `SkiaDrawingContext.cs:292,294`); a `null` is cached and then dereferenced in `Dispose()` (`:336-339`) at the end of the first frame. Text is drawn with a single `SKFont` per run (`:93,142-146`) — no `SKFontManager.MatchCharacter`/shaping — so mixed-script cells (Latin + CJK, emoji) render tofu unless an app registers a font that covers *every* glyph. All Skia objects are also rebuilt every frame (`:11-13, 324-342`; `DataGridView.cs:626`), contradicting the README's "no GC pressure" claim.
- **Keyboard and selection claims do not hold on Windows/Android.** Only characters, Backspace and Enter reach the grid through the hidden `Entry` (`DataGridView.cs:1045-1112`); arrows/Tab/Esc/F2/Home/End/PageUp/Down and Shift/Ctrl never arrive (no `#if WINDOWS` key hook; only `:647`). Pointer modifiers are never populated (`:714-728`), so `Extended` selection (the default, `:326`) can never do Shift-range/Ctrl-toggle on any platform. README `:526, :546` claim both.
- **The MAUI surface is not MVVM-complete for 1.0.** No `SelectedItem/SelectedItems/SelectionChanged`, no `ScrollTo*`, no public `Invalidate()`, `Theme`/`GridStyle`/`ScrollSettings` are plain CLR properties (no binding, no `AppThemeBinding`, no reaction to OS dark mode), `HeaderHeight`/`RowHeight` are silently discarded when `Theme`/`GridStyle` is set afterwards (attribute-order dependent), and the hidden keyboard `Entry` is exposed to screen readers while cell content is not.

## (d) Questions for the maintainer

1. **Platform floor for 1.0** — Is dropping macOS Catalyst 15/16 (and possibly iOS 15/16) acceptable now that the Xcode‑27 toolchain enforces 17.0 (MAUI-01)? Do you want CI pinned to a workload set, or to float and accept toolchain‑driven breaks?
2. **Keyboard support matrix** — Is "full keyboard navigation on all platforms" a 1.0 requirement, or should README be scoped to iOS/macOS (hardware keys) + mobile text entry until Windows/Android key hooks land (MAUI-03)?
3. **IME scope** — Is CJK *text entry* (not just display) in scope for 1.0? If yes, the hidden‑Entry design needs replacing with a native input connection (MAUI-27).
4. **Font aliasing** — Should `GridFont.Family` accept MAUI font aliases (`ConfigureFonts` names) transparently (host bridges them into `SkiaFontRegistrar`), or remain Skia‑family‑name based with documentation? This decides the fix shape for SKIA-01.
5. **Glyph fallback strategy** — `SKFontManager.MatchCharacter` run segmentation (small, no new deps) vs. `SkiaSharp.HarfBuzz`/`SKShaper` (correct shaping for Arabic/Indic, extra native dependency) for SKIA-02?
6. **Resource lifetime** — Are you open to moving the Skia object caches from per‑frame to per‑control/process (SKIA-03)? It changes the `SkiaDrawingContext` contract documented in `rendering.instructions.md:47-48,137-138`.
7. **Base class** — Is changing `DataGridView : Grid` to a `TemplatedView`/`ContentView` acceptable before 1.0 (MAUI-24)? It also lets you drop the `new IsReadOnly`.
8. **Inert properties** — Delete `IsReadOnly`/`AllowSorting`/`AllowFiltering` or implement them in Core (MAUI-02)? If implemented, should `AllowFiltering=false` hide the icon or only disable the popup?
9. **Threading contract** — Document "UI‑thread only" for data mutations, or marshal in the host (MAUI-12)?
10. **GPU rendering** — Any measured frame times on Android/Windows backing the "60 fps" claim? Would an opt‑in `SKGLView` mode be welcome (MAUI-14)?
11. **Images** — What is the intended source type for `Image` columns in MAUI apps (`ImageSource`, URL, bytes)? Who owns decode/caching (SKIA-09)?
12. **PR #1** — Is the AOT/trim PR still the plan (MAUI-23)? It conflicts conceptually with `ValueAccessor` delegates vs. `PropertyName` reflection; worth deciding before 1.0 since both are public API.
