# KumikoUI 1.0 readiness review — tests, CI/CD, packaging/versioning, repository hygiene

- Date: 2026-10-22. Reviewed tree: `feature/uno-platform-port` @ `4938125` (PR #9, base `develop`); `origin/main` @ `59825e2`; `origin/develop` @ `a11a5aa` (0 commits ahead of main).
- Scope: tests, CI/CD, packaging/versioning, repo hygiene, licensing of bundled assets. No repo files were modified; all build/test/pack output went to the scratchpad.
- Local toolchain used: .NET SDK 10.0.401 only (runtime 10.0.12 only; no 9.0 runtime) — itself the cause of one finding (TEST-06).

## (a) Summary

1. **Half the engine has no tests.** 72 of 120 public Core types are never referenced by any test; `DataGridRenderer` (1,786 LOC), `GridInputController` (1,510), every `Drawn*` editor (≈4,500 LOC), `EditSession`, `HitTesting`, `PaintCache` and `CellEditorFactory` have zero coverage. The 353 passing Core tests concentrate on models/layout math; there are no rendering, golden-image, SkiaSharp, MAUI or benchmark tests, and the README's "60 fps / 100K rows" claims are unmeasured.
2. **No release gate.** `main` has no branch protection or rulesets, the `nuget-publish` environment has no reviewers or branch policy, `workflow_dispatch` can publish any version string from any ref, and the publish `test` job only runs the Core suite (Uno tests are not in the gate). Three of ten tag publishes already failed and burned version numbers.
3. **Versioning and TFM policy are inconsistent with a 1.0.** Every csproj says `<Version>1.0.0</Version>` (a local `dotnet pack` produced `KumikoUI.Core.1.0.0.nupkg`) while NuGet has 0.1.x; Core/SkiaSharp/Uno target `net9.0` (STS, end of support **2026-11-10**, 19 days away) while Maui and the samples are `net10.0`; SkiaSharp 3.119.2 is pinned in seven places and is a full major behind (4.153.1); there is no CHANGELOG, no package validation baseline, no PublicAPI tracking.
4. **The embedded NuGet README will render broken on nuget.org** — it opens with raw HTML and relative image paths (`<img src="images/logo.svg">`), which NuGet.org does not render — and it is MAUI-only even though it ships inside KumikoUI.Core/SkiaSharp and (soon) KumikoUI.Uno.
5. **Repository hygiene is pre-1.0.** CONTRIBUTING.md (linked from PR #9 at a wrong org URL), SECURITY.md, CHANGELOG, PR template, .editorconfig, global.json, dependabot.yml and CodeQL are all missing; actions are 2–4 majors behind; the MAUI/Uno workload cache has never hit (every Windows job reinstalls workloads); PR #1 (NativeAOT) has been open and conflicting for 191 days with 7 unaddressed review comments; bundled fonts (Apache-2.0 and OFL-1.1) ship without their required license notices.
