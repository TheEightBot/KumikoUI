# 1.0.0 release checklist: status (#114)

**Status as of 2026-11-14.** The maintainer chose to cut **1.0.0-preview.1** of all four packages (KumikoUI.Core,
KumikoUI.SkiaSharp, KumikoUI.Maui, KumikoUI.Uno) instead of 1.0.0 now. This file was written on 2026-11-13 against
`integration/1.0-wave1` and the issue list on GitHub (read only), and updated on 2026-11-14 for the preview. It lets the
maintainer tick the boxes of [issue #114](https://github.com/TheEightBot/KumikoUI/issues/114); nothing on GitHub was edited
by this file.

Legend: `[x]` done, `[~]` partly, `[ ]` not done. "Done on the integration branch" means the work is committed on
`integration/1.0-wave1` but the GitHub issue is still open because that branch is not merged to `main`; close the issue
when it is. Issue states are as of the 2026-11-13 check. CI has not run on the integration branch (all verification was
local), so merging it to `main` and getting the required checks green comes before the tag.

## What 1.0.0-preview.1 changes

- **Version scheme (D-V) is settled for this release by previewing all four packages.** One tag, `v1.0.0-preview.1`,
  versions Core, SkiaSharp, Maui and Uno together, which is option (a) of the earlier decision table. The lockstep rule
  in [docs/VERSIONING.md](../VERSIONING.md) holds and the exact sibling pins (D3) stay. The earlier plan (Core, SkiaSharp
  and MAUI at 1.0.0, Uno alone at `1.0.0-preview`, option (c)) is not used. When `1.0.0` is cut it is again one tag for
  all four; whether Uno is ready for that is decided then, from the Uno verification results.
- **The Uno "GA or preview" question is moot for this release** (everything is a preview) but not closed for `1.0.0`:
  Uno remains the least verified host and the docs say so (README "Supported platforms", `docs/nuget/README.KumikoUI.Uno.md`,
  the release notes).
- **Docs are adapted for the preview:** CHANGELOG section `## [1.0.0-preview.1] - 2026-11-14` (the publish workflow needs
  that exact heading; `eng/changelog-section.sh` extracts it), README, the four NuGet READMEs, SECURITY, VERSIONING,
  CONTRIBUTING, ROADMAP, [release notes](1.0.0-preview.1-release-notes.md) and the [announcement draft](announcement-draft.md).
- **PublicAPI files stay in `Unshipped`** and the package validation baseline stays off for the preview; both change
  at `1.0.0`.
- **The Uno follow-ups are filed:** F1 desktop hands-on pass [#274](https://github.com/TheEightBot/KumikoUI/issues/274),
  F2 Android filter search gets no soft keyboard [#275](https://github.com/TheEightBot/KumikoUI/issues/275), F3 Android
  touch column reorder [#276](https://github.com/TheEightBot/KumikoUI/issues/276), F4 macOS desktop grid missing from the
  accessibility tree [#277](https://github.com/TheEightBot/KumikoUI/issues/277), F8 Android Release cold start
  [#278](https://github.com/TheEightBot/KumikoUI/issues/278), F9 iOS typing over a selection goes in front
  [#279](https://github.com/TheEightBot/KumikoUI/issues/279), F10 sample shell under the system bars
  [#280](https://github.com/TheEightBot/KumikoUI/issues/280). F5 (combo box Enter) is resolved as by design, and F6 and F7 are
  fixed in Core (`docs/uno/verification.md`).

## Bottom line

For **1.0.0-preview.1**, in the order they have to happen:

1. **Merge** `integration/1.0-wave1` to `main`; get `Build & Test`, the MAUI and Uno build jobs, snippets, identifiers and
   CodeQL green. Windows heads (MAUI `net10.0-windows*`, Uno desktop and WinAppSDK) have only ever been compiled in CI,
   never on this Mac, so this is the first time the integrated code builds for them.
2. **Rehearse** the publish workflow with dry run on, then tag `v1.0.0-preview.1` from `main` and approve the
   `nuget-publish` environment (see [CONTRIBUTING.md](../../CONTRIBUTING.md#versions-and-releases)).
3. **After the tag**: install the published packages (with `--prerelease`) into a fresh MAUI app and a fresh Uno app, look
   at the four package pages, then post the announcement.

What remains for **1.0.0**:

- `PublicAPI.Shipped.txt` freeze: run `eng/update-public-api.sh`, move `Unshipped` to `Shipped` (api-review-1.0.md, "Steps
  at the 1.0 tag"), build the Windows heads in CI so their per-TFM files are confirmed, and make the `Shipped` files live in
  CONTRIBUTING.
- Package validation baseline: set `PackageValidationBaselineVersion` after the stable tag (a preview is not a baseline).
- The open maintainer decisions below (D1 hex order, D2 editor factory shapes, Android `Auto` = Hardware on a physical
  phone, the HarfBuzz dependency).
- Hands-on passes on Windows (MAUI on Windows, Uno on Windows App SDK, Uno desktop on Windows and Linux) and on physical
  devices (a low-end Android phone, hover and haptics), and a screen-reader run (VoiceOver, TalkBack, Narrator).
- The open Uno issues #274 to #280, or an explicit decision to ship `1.0.0` with them listed.
- A `## [1.0.0]` CHANGELOG section (a stable tag fails to publish without it), fresh release notes and announcement.
