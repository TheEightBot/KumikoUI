# 1.0.0 release checklist: status (#114)

**Status as of 2026-11-25.** The maintainer is cutting **1.0.0**, the first stable release of all four packages
(KumikoUI.Core, KumikoUI.SkiaSharp, KumikoUI.Maui, KumikoUI.Uno), on the `release/1.0.0` branch, release date
2026-11-25. This file was written on 2026-11-13 against `integration/1.0-wave1`, updated on 2026-11-14 for
`1.0.0-preview.1`, and updated on 2026-11-25 for `1.0.0`. It lets the maintainer tick the boxes of
[issue #114](https://github.com/TheEightBot/KumikoUI/issues/114); nothing on GitHub was edited by this file. The tag and
the NuGet publish have not happened yet; they are the next steps below.

Legend: `[x]` done, `[~]` partly, `[ ]` not done. Issue states are as of the 2026-11-25 check (read only).

## What 1.0.0 does

- **One stable version for all four packages.** One tag, `v1.0.0`, versions Core, SkiaSharp, Maui and Uno together;
  the lockstep rule in [docs/VERSIONING.md](../VERSIONING.md) and the exact sibling pins (D3, `[1.0.0]`) hold. From this
  version on the compatibility rules of VERSIONING.md apply.
- **KumikoUI.Uno ships in 1.0.0 and is fully supported** (maintainer decision, 2026-11-25). The "least verified host" and
  preview callouts are removed from the README, `docs/nuget/README.KumikoUI.Uno.md`, `docs/uno/README.md`,
  `docs/uno/verification.md` ("Recommendation and decision") and the release notes. The open Uno items are tracked in
  the [1.0.1 milestone](https://github.com/TheEightBot/KumikoUI/milestone/5): #274 desktop hands-on pass, #276 Android
  touch reorder on a physical device, #277 macOS accessibility tree, #287 Linux AT-SPI table role, #292 Android head
  docs, #67 Uno device matrix.
- **The public API is frozen** (R2, #112): commit 3734b96 moves every `PublicAPI.Unshipped.txt` line into
  `PublicAPI.Shipped.txt` (Core 2403, SkiaSharp 86, MAUI 217, Uno 213 plus 5 per head), and every `Unshipped` file holds
  only `#nullable enable`.
- **CHANGELOG section** `## [1.0.0] - 2026-11-25` is cut (commit 05474df) with a fresh empty `## [Unreleased]` and the
  compare links updated; the publish workflow needs that exact heading (`eng/changelog-section.sh`).
- **The open maintainer decisions are taken** (table below): D1 (#304), D2 (#305), Uno ships, Android `Auto` stays
  Hardware, the HarfBuzz dependency is kept.
- **Docs are adapted for 1.0.0:** README, the four NuGet READMEs (stable badge, no `--prerelease`), SECURITY (`1.0.x`
  supported), VERSIONING, CONTRIBUTING (release example, `Shipped` files live), ROADMAP, `docs/uno/README.md`,
  `docs/uno/verification.md`, `docs/maui-verification.md`, the [release notes](1.0.0-release-notes.md) and the
  [announcement draft](announcement-draft.md).

## Bottom line

For **1.0.0**, in the order they have to happen:

1. **Merge** `release/1.0.0` to `main` through a pull request; get `Build & Test`, the MAUI and Uno build jobs (the only
   check of the Windows heads' public API: `net10.0-windows10.0.19041.0` on MAUI, `net10.0-windows10.0.26100` on Uno),
   snippets, identifiers and CodeQL green.
2. **Rehearse** the publish workflow with dry run on, then tag `v1.0.0` on that commit on `main` and approve the
   `nuget-publish` environment (see [CONTRIBUTING.md](../../CONTRIBUTING.md#versions-and-releases)). Tag without a package
   validation baseline (no earlier stable package exists).
3. **After the tag:** on the first commit after it, uncomment `PackageValidationBaselineVersion` with `1.0.0` in
   `Directory.Build.props` and reword its comment (api-review step 5); install the published packages (no
   `--prerelease`) into a fresh MAUI app and a fresh Uno app; look at the four package pages; post the announcement;
   close #112, #113 and #114.

Left after 1.0.0 (1.0.1 milestone and beyond):

- The Uno items in the 1.0.1 milestone (#274, #276, #277, #287, #292, #67).
- Hands-on passes on Windows (MAUI on Windows, Uno on Windows App SDK, the rest of Uno desktop on Windows) and on
  physical devices (a low-end Android phone for the hardware surface, hover and haptics), and a screen-reader run
  (VoiceOver, TalkBack, Narrator).
