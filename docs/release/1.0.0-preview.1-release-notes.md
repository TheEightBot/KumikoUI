# KumikoUI 1.0.0-preview.1 release notes

**Released:** 2026-11-14 (prerelease). This is the long form of the `## [1.0.0-preview.1] - 2026-11-14` section of
[CHANGELOG.md](../../CHANGELOG.md), which holds the per-change reference. The publish workflow copies that CHANGELOG
section, not this file, into the GitHub Release and the package release notes. Links below are repository-relative.

## [1.0.0-preview.1] - 2026-11-14

`1.0.0-preview.1` is the first 1.0 prerelease of the canvas-drawn DataGrid for .NET MAUI and the Uno Platform. All four
packages (KumikoUI.Core, KumikoUI.SkiaSharp, KumikoUI.Maui, KumikoUI.Uno) ship at this version and depend on each other at
exactly this version. A preview carries no compatibility promise: the public API has been through a full review for 1.0,
but it is not frozen, and it can still change before `1.0.0` (see [docs/VERSIONING.md](../VERSIONING.md)). Since 0.2.0 the
work was a last API review, a zero-allocation render path, background rebuilds for large data, device verification on
both hosts, interaction polish and complete documentation. KumikoUI.Uno is the least verified host: it shares the engine
and API with MAUI, but its heads have not all been walked end to end (see "Known issues").

### What a preview means and how to give feedback

- Install it explicitly: `dotnet add package KumikoUI.Maui --prerelease`, or `--version 1.0.0-preview.1`, or
  `Version="1.0.0-preview.1"` in a `PackageReference`. NuGet does not select a prerelease by default.
- Use the same version for every KumikoUI package; a mismatched set fails at restore.
- Breaking changes can land in `1.0.0-preview.2` or `1.0.0`. They are listed in the CHANGELOG with the **Breaking:** prefix.
- Report bugs and API problems as [GitHub issues](https://github.com/TheEightBot/KumikoUI/issues) (include the package
  version, host, platform and a minimal project) or start a discussion. Security reports go through GitHub's private
  vulnerability reporting ([SECURITY.md](../../SECURITY.md)).
- What `1.0.0` still waits for is in [1.0-checklist-status.md](1.0-checklist-status.md).

### Highlights

- **A reviewed public API.** Every public and protected member of the four packages was read once more against the
  .NET design guidelines (notes in `docs/release-readiness/api-review-1.0.md`). The public surface is tracked in the
  `PublicAPI.Unshipped.txt` files; it moves to `PublicAPI.Shipped.txt` and package validation turns on at `1.0.0`, after
  which an unintended breaking change fails the pack. Dead and unsafe surface was removed or made internal. The four
  packages depend on each other at their exact version, so a mismatched set fails at restore.
- **An allocation-free render loop, measured.** A steady-state frame allocates nothing in the managed render loop, also
  with an editor or a filter popup open, and nothing through the SkiaSharp drawing context. On an Apple M4 Max a 30 x 10
  frame takes 2.9 microseconds (6.3 with sorting, filtering, grouping, summaries, a frozen column and the drag handle)
  into a no-op context. Numbers, method and budgets are in [bench/README.md](../../bench/README.md); per-device frame rates
  are measured on the device with `ShowFrameStats`.
- **Large data stays responsive.** From 10,000 rows (`BackgroundRebuildThreshold`) a sort, filter or grouping change
  is computed on a worker from an immutable snapshot, coalesced and swapped in on the UI thread; the UI thread pays about
  1 ms for a sort of a million rows. Single-item collection changes and live summary updates stay incremental.
- **Text input that works with input methods.** Native text-input adapters on iOS and Mac Catalyst (`UITextInput`),
  Android (`InputConnection`), Windows (`CoreTextEditContext`) and Uno (composition events): Japanese, Chinese and
  Korean composition, emoji, dictation, undo and redo, clipboard, hardware keyboards and Tab that never traps focus.
- **Emoji and fonts.** Emoji sequences (skin tones, ZWJ families, flags) draw as one glyph, with per-glyph font fallback,
  and icon fonts and CJK through `SkiaFontRegistrar` (MAUI) or `KumikoFonts` (both hosts).
- **Verified on devices.** The MAUI sample passes a 106-check device suite on an Android 15 emulator, iPhone and iPad
  simulators and Mac Catalyst; the Uno sample was walked on WebAssembly, an iOS simulator and an Android emulator. Results
  and known issues: [docs/maui-verification.md](../maui-verification.md), [docs/uno/verification.md](../uno/verification.md).
- **Interaction polish.** Hover and pressed states, transitions for group expand and collapse and column drag,
  per-platform momentum presets, optional haptics, exact hit regions and a context-menu event; every threshold is
  listed in [docs/INTERACTION.md](../INTERACTION.md).
- **Keyboard avoidance.** The edited cell scrolls above the on-screen keyboard on iOS, Android and the Uno mobile heads.
- **Features since 0.1.x** (details in the 0.2.0 section): item-based selection with MVVM bindings, typed value
  conversion and validation, saved layouts (`KumikoLayoutState`), column reorder, image and progress bar columns,
  replaceable icon packs, clipboard copy, programmatic scrolling, bindable themes that follow the system, `KumikoStrings`
  localization, Native AOT and trimming support through generated accessors, and MAUI hardware (GPU) rendering.
- **Documentation.** A host-neutral README whose C# and XAML snippets are compiled in CI, a README per NuGet package, a
  user guide for Uno, regenerated architecture and rendering documents, and a sample app per host with the same nine pages.

### Breaking changes (since 0.2.0)

The 0.2.0 release carried the large API reshaping (naming, host base classes, selection, `ViewChanged`); upgrade from
0.1.x through its section first. The changes below are the ones made after 0.2.0. Most are fixed by recompiling and
following the compiler.

| Change | Migration |
|---|---|
| Parameterless `Action` events are `EventHandler`; the two value-carrying ones are `EventHandler<T>` (`KumikoInputController.NeedsRedraw`, `KeyboardFocusRequested`, `FilterPopupOpened`, `FilterPopupClosed`, `CursorChanged`, `EditSession.NeedsRedraw` and others) | Change `() => ...` handlers to `(sender, e) => ...`. |
| `KumikoFont` and `KumikoHitTestResult` are `readonly record struct`s | Build a changed font with `with` (`style.CellFont = style.CellFont with { Size = 16 }`). `KumikoHitTestResult.Empty` means nothing hit; `default` has indices 0. |
| `KumikoRect.Contains(x, y)` is half-open | A point on a cell's right or bottom edge now belongs to the next cell. |
| Leaf types are `sealed` (event arguments, models, descriptions, `KumikoColumn`, `KumikoSource`, `EditSession`, `KumikoInputController`, `KumikoStyle` and others) | Compose instead of deriving; the extension points are interfaces, delegates and the `Custom*` properties. |
| `PopupManager`, `DrawnFocusManager`, `DrawnCheckBox`, `DrawnProgressBar` and related types are `internal` | Use `KumikoInputController.ActivePopup` to observe the open popup. |
| `KumikoSource` is UI-thread-only; a change from another thread throws `InvalidOperationException` | Post the change to the UI thread; build a new collection in the background and assign it on the UI thread. |
| `KumikoSource.BeginUpdate()` returns `KumikoUpdateScope` | Recompile; prefer `using (source.BeginUpdate()) { ... }`. |
| A `PropertyChanged` of a property only table summaries use no longer rebuilds the view and raises `ViewChanged` as `Redraw` | Handlers that expected `Rebuild` for such a change should treat `Redraw` as "values changed". |
| `KumikoPaint.Style` and `PaintStyle` removed; `KumikoCellStyle.BorderColor` and `BorderWidth` removed | Nothing honored them. Draw borders in a custom renderer or use the grid-line properties of `KumikoStyle`. |
| `KumikoLayoutEngine.GetVisibleRowRange`, `GetVisibleColumns`, `HitTestColumn`, `HitTestRow`, `GetColumnX` removed; `HitRegion.RowHeader` and `FrozenColumn` removed; `DrawnTextBox.ValidationMessage` removed; `KumikoColumn.Id` removed | Use `GetVisibleRowRangeWithOffset`, `GetVisibleFrozenColumns`, `GetVisibleScrollableColumns` and `KumikoHitTester`; identify a column by reference or `PropertyName`. Numeric `HitRegion` values after `HeaderFilterIcon` shift down. |
| API review renames: `KumikoColor.ToUint32()` to `ToUInt32()`, `KumikoMomentumPreset.Ios` to `IOS`; parameter names `rowIndex` and `columnIndex`; `KumikoSelectionModel` navigation methods lost unused parameters; `KumikoHitTester.HitTest` is one method; `IDrawingContext.DrawTextInRect` has no optional parameters; `ComputedSummaryRow.Values` is read-only; `KumikoSelectionModel.IsEditing` is read-only | Recompile and follow the compiler. The full list is in the `Unreleased` entry "API review for 1.0". |
| MAUI: `KumikoRenderMode.Gpu` is `Hardware`; Uno's `Software` and `Hardware` swap numeric values | Rename in code and XAML. `Auto` (the default) uses the hardware surface on Android and Mac Catalyst and the software surface on iOS and Windows; set `RenderMode="Software"` to keep CPU rendering everywhere. |
| MAUI: `UseSkiaKumikoUI()` removed | Call `UseKumikoUI()`. |
| MAUI: `MauiActionButtonDefinition.BackgroundColor` and `TextColor` are `Microsoft.Maui.Graphics.Color` | Use `#0D6EFD`, a named color, a resource or `AppThemeBinding`; the `R,G,B` text form is no longer accepted there. |
| MAUI and Uno: `ScrollToColumn` has four overloads instead of two with an optional parameter | Recompile. |
| Uno: `InputMapping` and `UnoActionButtonDefinition.Changed` are `internal`; `UnoActionButtonDefinition` is `sealed` | None for normal use. |
| The Android heads no longer ship a public generated `Resource` class | Use your app's own resources. |
| All KumikoUI packages depend on each other at an exact version (`[1.0.0-preview.1]`) | Keep all four on one version; a mismatch fails at restore. |

### Behavior changes

- Only the primary mouse button (or a finger) selects, sorts, scrolls, drags and edits. A right click, or a long press by a
  finger or pen, raises `ContextMenuRequested` instead of sorting, editing or dragging. Pointer actions fire once, on the
  release, on the pressed target.
- A user's column drag now also moves the column in the grid's `Columns` collection, so adding a column later does not undo
  the drag. `ColumnReordered` is raised by the grid.
- Frozen columns that do not fit a narrow grid are unpinned (up to `KumikoStyle.MaxFrozenColumnsWidthRatio`, two thirds by
  default) instead of covering the scrolling columns.
- Uno: the grid no longer sets `IsTabStop` or `TabIndex` itself, so it takes its natural place in the tab order.
- Uno: a touch or pen long press is detected by a 500 ms timer, as on MAUI, and the release that ends it does not tap.
- Built-in glyphs (filter funnel, sort arrows, editor buttons) are drawn by the new icon provider and look slightly
  different from 0.2.0.
- `KumikoColorTypeConverter` accepts CSS color names, `#RGB` and `#ARGB`, and throws a `FormatException` naming the bad text.
  An 8-digit hex value stays `#AARRGGBB`.

### Fixed highlights

- Setting a two-way bound `SelectedItem` from the view model no longer hangs the UI thread (#267).
- Frozen panes wider than the grid no longer hide every scrolling column on a phone (#268).
- Uno on Android: typing in a cell editor no longer crashes the app, and typing over a selected value replaces it (#67).
- Uno: typing at the end of an editor or the filter search box no longer throws `ArgumentOutOfRangeException`.
- Emoji with skin-tone modifiers, ZWJ sequences and flags draw as one glyph (#259).
- Summary values are clipped to their column and pane.

### Known issues

Each item is a real limitation in `1.0.0-preview.1`. The Uno ones come from [docs/uno/verification.md](../uno/verification.md)
and are tracked as issues; the MAUI ones come from [docs/maui-verification.md](../maui-verification.md).

**Platform coverage**

- KumikoUI.Maui on Windows and KumikoUI.Uno on Windows App SDK, Windows desktop and Linux desktop are built in CI but
  have not been run on a device.
- KumikoUI.Maui on Android has run only on an emulator; a physical low-end Mali or Adreno phone is the realistic risk for
  the hardware (GPU) surface, which `RenderMode = Auto` selects on Android. `RenderMode = Software` is the escape hatch.
- Hover and haptics have not been checked on a physical Android device, and pressed feedback and transitions have not been
  checked by eye on the Uno heads.
- No screen reader (VoiceOver, TalkBack, Narrator) was driven in the verification passes.

**KumikoUI.Uno** (the least verified host)

- The desktop head has had no hands-on pass with pointer and keyboard on macOS, Windows or Linux (#274). On macOS it
  renders, but no pointer or keyboard input was delivered to it in the verification run; its input code is shared with the
  WebAssembly head, which passed.
- macOS desktop: VoiceOver cannot reach the grid, because the accessibility tree has no element for it (#277).
- Android: tapping the filter popup's search box does not show the soft keyboard, so the search cannot be typed into on a
  phone. Cell editors are not affected (#275).
- Android: slow touch drags of a column header did not start a column reorder in an `adb` run; it needs a check with a
  finger (#276).
- Android: the Release build takes 15 to 20 seconds to the first grid on the emulator (#278).
- iOS: typing over a selected cell value goes in front of it ("Kim LeeEve Davis"). Typing at the end works (#279).
- Sample app on iOS and Android: the page title and toolbar run under the status bar and the bottom row under the gesture
  bar (#280).

**All hosts**

- The grid is one accessible element: cells are not exposed individually (a per-cell accessibility tree is planned for
  1.x), right-to-left layout is not mirrored (1.x), and the grid draws no scrollbars.

### Decisions still open before 1.0.0

These are maintainer decisions, not bugs; each changes the API or a default and is easier to take before `1.0.0`.

- The order of 8-digit hex colors in `KumikoColorTypeConverter` (`#AARRGGBB` is recommended and is what it does now).
- Whether to consolidate the legacy custom-editor factory path into `CellEditorContext`.
- Whether `RenderMode = Auto` stays Hardware on Android (to be confirmed on a physical low-end phone).
- Whether to accept the HarfBuzz dependency for complex scripts (about 172 KB more WebAssembly).

### Upgrading

1. Update all four packages you use to `1.0.0-preview.1`, with `--prerelease` or an explicit version.
2. MAUI: replace `UseSkiaKumikoUI()` with `UseKumikoUI()` and `KumikoRenderMode.Gpu` with `Hardware`.
3. Fix event handler signatures and the other compile errors from the table above.
4. Uno: set `<SkiaSharpVersion>4.153.1</SkiaSharpVersion>` and the `SkiaRenderer` Uno feature in the app project.
5. Make collection and item changes on the UI thread.
