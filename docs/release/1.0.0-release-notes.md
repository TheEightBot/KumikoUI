# KumikoUI 1.0.0 release notes

**Release date:** 2026-11-25. This is the long form of the `## [1.0.0] - 2026-11-25` section of
[CHANGELOG.md](../../CHANGELOG.md), which holds the per-change reference. The publish workflow copies that CHANGELOG
section, not this file, into the GitHub Release and the package release notes. Links below are repository-relative.

## [1.0.0] - 2026-11-25

`1.0.0` is the first stable release of the canvas-drawn DataGrid for .NET MAUI and the Uno Platform. All four packages
(KumikoUI.Core, KumikoUI.SkiaSharp, KumikoUI.Maui, KumikoUI.Uno) ship at this version and depend on each other at exactly
this version. KumikoUI.Uno ships with the other three and is fully supported. These notes cover the changes since
`1.0.0-preview.1` (2026-11-14); coming from 0.2.0, read the
[1.0.0-preview.1 release notes](1.0.0-preview.1-release-notes.md) first, since most of the 1.0 work landed there.

### What 1.0.0 means

- Install it like any stable package: `dotnet add package KumikoUI.Maui` or `dotnet add package KumikoUI.Uno`; no
  `--prerelease` is needed.
- Use the same version for every KumikoUI package. The sibling dependencies are exact (`[1.0.0]`), so a mismatched set
  fails at restore.
- The compatibility rules of [docs/VERSIONING.md](../VERSIONING.md) apply from this version on: a breaking change to the
  public API or documented behavior waits for the next major, and a removal is preceded by `[Obsolete]` for at least
  one minor release.
- The public surface is frozen in the `PublicAPI.Shipped.txt` files of the four packages (#112).
- Supported versions are `1.0.x` ([SECURITY.md](../../SECURITY.md)). The `1.0.0-preview.N` and `0.x` releases get no
  more fixes.
- Report bugs as [GitHub issues](https://github.com/TheEightBot/KumikoUI/issues) (include the package version, host,
  platform and a minimal project). Security reports go through GitHub's private vulnerability reporting.

### Highlights since 1.0.0-preview.1

- **The API is frozen.** The open API decisions from the review are taken: 8-digit hex stays `#AARRGGBB` (#304) and
  custom editors have one factory shape, `CellEditorContext` (#305).
- **`rgb()` and `rgba()` colors.** Every `KumikoColor` property in XAML accepts `rgb(r, g, b)` and `rgba(r, g, b, a)`
  beside hex and color names (#304).
- **SkiaSharp 4.157.0 and Uno.Sdk 7.** KumikoUI.Uno is built with Uno.Sdk 7.0.22, and KumikoUI.Maui needs
  `Microsoft.Maui.Controls` 10.0.110 or later.
- **Touch header interaction.** A long press on a column header now starts a column drag when the finger moves (#288),
  and the finger's resize grip leaves room to reorder narrow columns (#289).
- **KumikoUI.Uno is fully supported.** Since the preview its desktop head was walked on Linux (X11) and Windows, and the
  Android soft keyboard, Release cold start, iOS typing and sample shell issues were closed (#275, #278, #279, #280). The
  remaining verification items are tracked for 1.0.1 (see "Known limitations").

### Breaking changes (since 1.0.0-preview.1)

| Change | Migration |
|---|---|
| One custom-editor factory shape (#305): `KumikoColumn.CustomEditorFactory`, `EditorDescriptor.CreateEditor(object?, KumikoRect)` and `ICellEditorProvider.CreateEditor(object?, KumikoRect)` are removed; `EditorDescriptor.CreateEditor(CellEditorContext)` is the abstract member | Replace `CustomEditorFactory = (value, bounds) => ...` with `EditorFactory = context => ...`, override or implement `CreateEditor(CellEditorContext context)`, and read `context.Value` and `context.Bounds`. The built-in editors behave as before. |
| SkiaSharp 4.157.0 (was 4.153.1), which needs Uno.Sdk 7 / Uno.WinUI 7 and `Microsoft.Maui.Controls` 10.0.110 | MAUI: update `Microsoft.Maui.Controls` to 10.0.110 or later. Uno: move to Uno.Sdk 7 (`global.json`) and set `<SkiaSharpVersion>4.157.0</SkiaSharpVersion>`. |
| Uno.Sdk 7.0.22 adds `HarfBuzzSharp.NativeAssets.*` at 14.4.0.100, while the managed HarfBuzzSharp that SkiaSharp.HarfBuzz 4.157.0 uses needs 14.4.0.200 | If restore fails with NU1605, reference the `HarfBuzzSharp.NativeAssets.*` packages of your heads at 14.4.0.200, as `samples/SampleApp.Uno/SampleApp.Uno.csproj` does. |
| The sibling dependencies are `[1.0.0]` | Update all four packages together. |

### Behavior changes

- A touch long press on a column header that can be reordered holds the header instead of opening the header menu:
  moving past the drag slop (8 px) lifts the column, and releasing without moving raises `ContextRequested`
  (`KumikoContextTrigger.LongPress`) on the release instead of at 500 ms (#288). A header whose `AllowReorder` is false,
  a mouse or pen, a right click and a long press on a cell behave as before.
- The default `KumikoStyle.TouchColumnResizeGripWidth` is 24 px (was 32), and a finger's grip reaches at most a fifth of
  a column into it on each side of a border (at least 8 px), so a press near the right of a narrow header reorders
  instead of resizing (#289). Set it back to 32 for the old touch grip. The mouse and pen grip is unchanged.
- KumikoUI.Uno lists the `Skia` Uno feature (Uno 7 ignores `SkiaRenderer` in a library) and references
  `SkiaSharp.Views.Uno.WinUI` on every non-Windows head. Apps keep `SkiaRenderer` in their own `UnoFeatures`.

### Fixed

- Uno: a mouse press or release that names no button and has no button pressed is ignored, so a wheel notch on Uno's
  X11 host no longer selects the cell under the pointer or opens its editor (#286). The wheel itself does not scroll on
  X11 until Uno fixes [unoplatform/uno#26709](https://github.com/unoplatform/uno/issues/26709).
- Uno on Android: the explicit soft-keyboard show for the filter popup's search box is repeated once the press has
  settled (#275).
- Touch: the resize grips of a narrow header leave at least 60 percent of it for a reorder (#289).
- Uno sample: the shell pads itself by the visible bounds on iOS and Android (#280), and the pane's menu button no
  longer covers the page title on a phone (#291).

| Two custom-editor factory shapes (D2) | Consolidate on `CellEditorContext` (#305). |
| KumikoUI.Uno in the stable release | Ships in `1.0.0`, fully supported; open items in the 1.0.1 milestone. |

### State of support

The per-head matrix is in the README's [Supported platforms](../../README.md#supported-platforms); the runs behind it
are in [docs/maui-verification.md](../maui-verification.md) and [docs/uno/verification.md](../uno/verification.md).

- **KumikoUI.Core and KumikoUI.SkiaSharp:** unit tests in CI.
- **KumikoUI.Maui:** a 106-check device suite passes on an Android 15 emulator, iPhone and iPad simulators and Mac
  Catalyst.
- **KumikoUI.Uno:** the sample was walked on WebAssembly (Chromium), an iOS simulator, an Android 15 emulator and the
  desktop head on Linux (X11) and Windows.

### Known limitations

**Platform coverage**

- KumikoUI.Maui on Windows and KumikoUI.Uno on the Windows App SDK head are built in CI but have not been run on a
  device.
- Neither host has run on a physical Android phone. `RenderMode = Auto` selects the hardware (GPU) surface on Android;
  it has not yet been confirmed on a physical low-end Mali or Adreno phone, so if a driver misdraws, set
  `RenderMode = Software`.
- Hover and haptics have not been checked on a physical Android device, and pressed feedback and transitions have not
  been checked by eye on the Uno heads.
- No screen reader (VoiceOver, TalkBack, Narrator, Orca) was driven in the verification passes.

**KumikoUI.Uno**, tracked in the [1.0.1 milestone](https://github.com/TheEightBot/KumikoUI/milestone/5):

- macOS desktop: pointer and keyboard input has not been checked; the input code is shared with the WebAssembly and
  Linux heads, which passed (#274).
- macOS desktop: VoiceOver reaches the grid only on the page the app opens with, in a Release build; the cause is in
  Uno's macOS accessibility bridge (#277).
- Linux desktop: the grid is in the AT-SPI tree as a plain panel with its name and description, but with no table role
  and no current cell, so Orca cannot navigate it as a grid (#287).
- Android: a touch column reorder did not start on the emulator with injected swipes, which may not match a real finger; a check on a physical device is pending (#276).
- Linux desktop: the mouse wheel does not scroll on Uno's X11 host (upstream, see "Fixed").

**All hosts**

- The grid is one accessible element: cells are not exposed individually (a per-cell accessibility tree is planned for
  1.x), right-to-left layout is not mirrored (1.x), and the grid draws no scrollbars.

### Upgrading

From `1.0.0-preview.1`:

1. Update all four packages you use to `1.0.0`.
2. Replace `CustomEditorFactory` and the `(object?, KumikoRect)` editor overrides with the `CellEditorContext` forms.
3. MAUI: use `Microsoft.Maui.Controls` 10.0.110 or later.
4. Uno: move to Uno.Sdk 7, set `<SkiaSharpVersion>4.157.0</SkiaSharpVersion>`, and add the
   `HarfBuzzSharp.NativeAssets.*` references at 14.4.0.200 if restore reports NU1605.
5. If you relied on the 32 px touch resize grip, set `TouchColumnResizeGripWidth` back to 32.

From 0.2.0: follow the "Upgrading" steps of the [1.0.0-preview.1 release notes](1.0.0-preview.1-release-notes.md)
first (except its SkiaSharp version, which is 4.157.0 now), then the steps above.
