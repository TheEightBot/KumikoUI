# Competitor data grid features KumikoUI lacks: research notes

Which data grid features do the major paid .NET grid vendors ship that KumikoUI does not support yet? This document lists each one as a concrete, issue-ready gap, so the maintainer can pick features for the next release and turn them into GitHub issues.

- **Date:** 2026-11-26, at commit `4c2be0e` (`main`).
- **Vendors and products:**
  - **TK**, Progress Telerik: .NET MAUI `RadDataGrid` (and `RadTreeDataGrid`), WinUI `RadDataGrid`, WPF `RadGridView`, Blazor `TelerikGrid`.
  - **SF**, Syncfusion: MAUI, WinUI and WPF `SfDataGrid` (MAUI `SfTreeGrid` where relevant), Blazor `SfGrid`. Syncfusion ships no Uno grid.
  - **DX**, DevExpress: MAUI `DataGridView`, WinUI `GridControl` (discontinued, checked at table-of-contents level only), WPF `GridControl`, Blazor `DxGrid`.
  - **C1**, MESCIUS ComponentOne: `FlexGrid` for MAUI, WinUI, WPF and Blazor.
  - **IG**, Infragistics: no native MAUI grid. It documents only Ignite UI for Blazor hosted in a MAUI Blazor Hybrid app. Desktop is WPF `xamDataGrid`; Blazor is `IgbGrid`.
- **KumikoUI side:** `KumikoDataGrid` on MAUI and Uno as of `main` (`1.0.0-preview.1` plus Unreleased). Sources: `README.md`, `CHANGELOG.md`, `docs/specs/*`, and the `PublicAPI.Unshipped.txt` files. A few points were confirmed by grepping `src`; those are named in the row.
- **Method:** four vendor feature catalogs were researched on 2026-11-25/26 from primary vendor sources only: docs, API references, official samples and product pages. Telerik has 279 rows, Syncfusion 352, DevExpress 317, and MESCIUS plus Infragistics 294, with 16 Xceed-only rows. A separate inventory of KumikoUI `main` was taken the same day. Every vendor mark and every vendor URL below is copied from those catalogs. The catalogs are working notes and are not committed. `docs/release-readiness/07-external-research.md` (October 2026) was used as a cross-check only.
- **Tracking issues:** every gap is a GitHub issue in the [1.1 – Grid feature gaps](https://github.com/TheEightBot/KumikoUI/milestone/6) milestone (#315 to #412), linked from its row below. The issues were opened in order of expected value and use, which is not the same as the counting rule in the summary: the issue order also weighs the high-impact items listed after the summary table and the dependencies between gaps. Lower issue numbers rank higher, and the `priority:` labels follow the same order. Corrections to the KumikoUI status found while writing the issues are recorded in the issues, not here.
- **Labels:** **(inferred)** marks a judgment of mine rather than a fact read in a source. Every rank tie-break by impact, every size and every release bucket is inferred. Every other statement is tied to a vendor doc URL in the row or to a KumikoUI source named in the row.

## How to read the tables

**Vendor cells** show three marks, `M/D/B`: **M**AUI, **D**esktop (the stronger of WinUI and WPF), **B**lazor.

| Mark | Meaning |
|---|---|
| Y | Built in and documented for that product |
| P | Partial: a KB article, an official sample, a workaround, or a pairing with a separate vendor control or library |
| A | MESCIUS only: present in the API reference, no feature topic |
| K | MESCIUS only: claimed only on a key-features or product page |
| R | MESCIUS only: mentioned only in release notes |
| Y\* | MESCIUS only: provided by the ComponentOne DataCollection library, not documented as a grid topic |
| BH | Infragistics MAUI only: available by hosting the Ignite UI for Blazor grid in a MAUI Blazor Hybrid app, not a native MAUI control |
| XG | Infragistics WPF only: in the retired `xamGrid`, not in `xamDataGrid` |
| – | Not found in that product's docs. **This does not prove the feature is absent** (see [Caveats](#5-caveats)) |

**KumikoUI status:** **Absent** (nothing public), **Partial** (some of it exists; the cell says what is missing), **Spec-only #NNN** (designed in `docs/specs`, not implemented; the spec issues are closed as "spec delivered" and no implementation issue is open).

**Size (inferred):** **S** = one component or hook, days. **M** = several components or a new drawn surface, one to three weeks. **L** = architectural, or multi-week with prerequisites.

**Bucket (inferred):** **next** = next minor release, **later** = a later 1.x release, **skip** = probably skip.

**High-impact gaps that the counting rule ranks lower (inferred).** The rule rewards breadth on MAUI. These items matter more than their rank suggests:

- [A11Y-01](#a11y-01): a per-cell accessibility tree (spec #79). This is a compliance requirement, not a parity item. No vendor documents it natively on MAUI, but every vendor except MESCIUS documents it on desktop or Blazor.
- [LOD-06](#lod-06): drawn scrollbars. KumikoUI draws none, while every native-scroller grid gets platform scrollbars implicitly. This hurts desktop, Uno WebAssembly and Mac Catalyst most.
- [TCH-01](#tch-01): swipe row actions. SF and DX ship them on MAUI. They are a core mobile list idiom.
- [SEL-02](#sel-02): a checkbox selection column (spec #106). This is the usual touch alternative to Ctrl/Shift multi-select.
- [CTX-01](#ctx-01) and [CTX-02](#ctx-02): built-in drawn menus. MAUI cannot open a native menu at a point, so today every app builds its own. These menus would also give touch users copy, hide-column and group.
- [A11Y-02](#a11y-02): right-to-left layout (spec #80). Without it, Arabic and Hebrew apps cannot use the grid.

## 3. Where KumikoUI is ahead

These are features KumikoUI has today that most of the five vendors do not document on MAUI. Vendor marks are from the same catalogs.

- **Uno Platform.** KumikoUI's MAUI and Uno controls expose the same members. Syncfusion ships no Uno grid. Infragistics' Uno grid packages are alpha/beta trials with no help site. DevExpress discontinued its WinUI suite. The Telerik and MESCIUS catalogs record no Uno grid.
- **Touch column resize and reorder.** Telerik's MAUI resize is desktop-only. DevExpress MAUI has no interactive resize or reorder in its member list. KumikoUI has a 24 px touch resize grip and long-press header reorder (Uno Android reorder is still open, #276).
- **Keyboard navigation on every platform with a hardware keyboard.** Telerik documents MAUI keyboard support for Windows and Mac Catalyst only. DevExpress MAUI documents none.
- **Row drag-and-drop reorder.** It is not found for Telerik MAUI. MESCIUS MAUI has it in the API reference only. Syncfusion and DevExpress have it.
- **Clipboard copy.** Telerik MAUI and DevExpress MAUI document no clipboard support. Syncfusion has it.
- **Layout persistence** (versioned, AOT-safe JSON). Telerik MAUI and DevExpress MAUI document none. MESCIUS MAUI claims it only on a marketing page. Syncfusion has it.
- **Sticky group headers.** They are not documented for Telerik MAUI, DevExpress MAUI or Syncfusion MAUI. Syncfusion has frozen group captions on WinUI and WPF only.
- **Right-frozen columns, multi-level grouping and group footers on MAUI.** Telerik MAUI freezes left only. DevExpress MAUI groups one level only and has no group footers.
- **Action-button and image columns on MAUI.** Telerik MAUI has neither a command column nor an image column. DevExpress MAUI offers swipe items instead of a command column.
- **Screen-reader announcements.** These cover the current cell, sort, edit and validation. DevExpress and Syncfusion document only `AutomationId` on MAUI; Telerik documents nothing for MAUI. This is not a per-cell tree ([A11Y-01](#a11y-01)).
- **Narrow-screen frozen-pane unpinning** (`MaxFrozenColumnsWidthRatio`). None of the four catalogs records an equivalent **(inferred: absence of evidence)**.
- **Background (off-UI-thread) sort, filter, group and summaries, with an allocation-free render loop enforced in CI.** No MAUI vendor documents an equivalent. The closest is DevExpress WPF's Instant Feedback, which is a server mode **(inferred: absence of evidence)**.

## 5. Caveats

- **"Not documented" is not "absent".** Every vendor mark records what the vendor's docs, API reference, samples or product pages show. A `–` means the researcher found no documentation, not that the feature cannot be built. Marks in [LOD-06](#lod-06) (scrollbars) are the clearest under-count.
- **Desktop marks merge WinUI and WPF.** A desktop `Y` can mean WPF only, which is common for DevExpress, Telerik and Infragistics. The catalogs keep the per-platform detail.
- **Infragistics has no native MAUI grid.** Every IG MAUI mark is `BH` (the Blazor grid hosted in a MAUI Blazor Hybrid app) or `–`. The `Infragistics.WinUI.DataGrid.Trial` and `Infragistics.Uno.DataGrid.Trial` packages are alpha/beta with no help site. IG Blazor docs carry React wording in places, and IG Blazor paste is "planned", not shipped.
- **MESCIUS MAUI documentation is thin.** It has 14 topic pages and nothing on sorting, grouping, row details, paging, clipboard, keyboard, validation or touch. Many C1 MAUI marks are therefore `A`, `K` or `R`. Two contradictions affect rows here:
  - The MAUI paging claim ([PAG-01](#pag-01), `K`) has no pager class in the MAUI API.
  - The MAUI PDF export claim ([EXP-03](#exp-03), `K`) conflicts with an export format enum that has no PDF member.
  - Also, the MAUI pop-up edit form (EDT-01) is a marketing claim only, and the WPF edition split (.NET vs .NET Framework) changes which desktop features exist.
- **DevExpress WinUI is discontinued.** It was checked at table-of-contents level only, so DX desktop marks are effectively WPF. The DX MAUI column chooser and search bar are app-level samples, hence `P` in [CSZ-01](#csz-01) and [FLT-03](#flt-03). DX MAUI does not document DataTable or ExpandoObject either way. DX Blazor "batch editing" is a demo and a GitHub example, not an edit mode.
- **Telerik MAUI export is KB-only.** Two KB articles build XLSX and PDF by hand with Telerik Document Processing and say direct PDF export "is not supported", hence `P` in EXP-01 to EXP-03. Further Telerik notes:
  - MAUI keyboard support and column resize are desktop-only.
  - `ScrollItemIntoView` assumes equal row heights, while content-sized rows are the default.
  - The WinUI docs repository is private now, so some WinUI marks rest on the API reference alone.
- **Syncfusion has two drifting doc trees.** MAUI Multi-Row View (HDR-02) and the AI pages exist only in the legacy `help.syncfusion.com/maui/...` tree. Further Syncfusion notes:
  - MAUI printing (PRT-01), RTL (A11Y-02) and dialog editing (EDT-01) are official samples, not UG features, hence `P`.
  - MAUI serialization does not list a filtering option, so whether filters persist on MAUI is unclear (STA-01).
- **Cross-check with `docs/release-readiness/07-external-research.md` (October 2026).** Several gaps it ranked have since shipped and are not listed here: column reorder, a validation UI, built-in string localization, clipboard copy, `ScrollTo*`, the context-request event and multi-aggregate summaries. It also counted tree grids, search-as-you-type and tooltips as rare (0 or 1 of 7 products). The newer catalogs find them on MAUI at Telerik (`RadTreeDataGrid`, search), Syncfusion (`SfTreeGrid`, search, tooltips) and MESCIUS (tree grid, search). The difference comes from wider doc coverage, not from new vendor releases **(inferred)**.
- **KumikoUI status** comes from `main` at `4c2be0e`. "Spec-only" designs are drafts awaiting review. Their GitHub issues (#79, #80, #102 to #111) are closed as "spec delivered", and no implementation issue exists yet. A few statuses were confirmed by grepping `src`: no `DataAnnotations` use, no header text wrapping, no grouped-column hiding, no selection-changing cancel, a single `DataItem` in `RowReorderedEventArgs`, and no scroll axis lock. Each is named in its row.
- **Ranking, sizes and buckets are judgments (inferred).** Ranking counts vendors, not market share. A feature that one large vendor ships on MAUI counts the same as one shipped by a vendor with thin docs.
